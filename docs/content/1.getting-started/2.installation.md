---
title: "Installation"
description: "Add @happydesigns/ui to a Nuxt project and prepare the generated Nuxt types."
---
Install the layer together with the styling packages used by the application's CSS entry point.

```bash
pnpm add @happydesigns/ui @nuxt/ui tailwindcss
```

Then extend the package and register one application-owned stylesheet from the project `nuxt.config.ts`.

```ts
export default defineNuxtConfig({
  extends: ['@happydesigns/ui'],
  css: ['~/assets/css/main.css'],
})
```

Create `app/assets/css/main.css` with the framework imports first and the shared layer styles last.

```css
@import "tailwindcss";
@import "@nuxt/ui";
@import "@happydesigns/ui/styles.css";
```

Keep this as the application's only stylesheet that imports Tailwind or Nuxt UI. Tailwind processes independently registered stylesheets in separate compilation contexts; a single root ensures that the generated Nuxt UI themes, responsive variants, project theme values, and layer components use the same source graph.

Project-specific `@theme`, base, component, or utility rules belong below these imports in the same file.

Run Nuxt preparation after changing dependencies or layer configuration.

```bash
pnpm exec nuxt prepare
```

## Content collections

Nuxt Content configuration is project-owned. The layer exports source-agnostic schema profiles and recommended indexes; each application chooses its own collection names, sources, prefixes, and additional fields.

```ts [content.config.ts]
import { articleCollectionIndexes, collectionSchemas } from '@happydesigns/ui/schemas'
import { defineCollection, defineContentConfig } from '@nuxt/content'
import { z } from 'zod'

export default defineContentConfig({
  collections: {
    news: defineCollection({
      type: 'page',
      source: {
        include: 'news/**/*.{md,yaml}',
        prefix: '/updates',
      },
      schema: collectionSchemas.article.extend({
        featured: z.boolean().default(false),
      }),
      indexes: articleCollectionIndexes,
    }),

    legal: defineCollection({
      type: 'page',
      source: 'legal/**/*.md',
      schema: collectionSchemas.content,
    }),
  },
})
```

Collection names are not prescribed. Pass the chosen name to components such as `HArticleList`, `HArticlePage`, `HSnippet`, and the shared layouts. A project that does not use Nuxt Content does not need a `content.config.ts`.
## Required peer setup

The layer is built for Nuxt 4.5.1, Nuxt UI 4.10, Nuxt Content 3, Tailwind CSS 4, and the happydesigns variants module. A project that extends it should already be a Nuxt app and should keep its lockfile committed after installation.

The package exports the layer from `nuxt.config.ts`, so projects extend the package name rather than importing runtime files manually. Tailwind CSS is a peer dependency because the application's stylesheet owns the compiler entry point.

## Package entry points

| Entry                         | Use                                                                                       |
| ----------------------------- | ----------------------------------------------------------------------------------------- |
| `@happydesigns/ui`            | Nuxt layer entry.                                                                         |
| `@happydesigns/ui/schemas`    | Content schema exports for projects that need to compose or inspect the collection model. |
| `@happydesigns/ui/styles.css` | Shared CSS fragment imported after Tailwind and Nuxt UI in the application stylesheet.    |
| `@happydesigns/ui/types`      | Public app-config and search types.                                                        |

Do not import internal files from `app/` or `schemas/` by path. If a project needs something that is not exported, add a stable export instead of depending on repository layout.
