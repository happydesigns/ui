---
title: "App shell and layouts"
description: "How the layer supports shared app structure without owning every project page."
---
The layer provides shared building blocks for page structure, but projects still own their routes and final app shell. This keeps the package reusable for different website types and product apps.

## What the layer provides

- Shared components for article-like pages, lists, footers, snippets, and content traits.
- A shared `content` layout for content-backed pages, from long-form reading to listings, galleries, forms, maps, and application UI.
- An explicit `toc` switch that controls whether the content layout reserves its right column.
- App config keys for header links, footer links, GitHub source links, dates, and icons.
- Defaults for collection behavior, list rendering, and trait rendering.

## What projects provide

- The route tree.
- The project homepage and custom pages.
- The final layout composition.
- Brand assets, project CSS, and project-specific content.

This split lets a project use the same content and UI foundation without being forced into one fixed app structure.

## Choose layout and table of contents independently

Use `content` whenever Nuxt Content owns the title, description, header, or SEO metadata. Set `toc: true` for a right-hand table-of-contents column and `toc: false` for the full content container. The collection name is independent of this behavior: every content-backed collection composes the `content` variant, even when a project keeps separate collections for different sources or queries.

Keep `default` for routes that own their metadata and composition completely. Use `article` for article-like collections with breadcrumbs, metadata, actions, and surrounding navigation.
## Root app contract

The layer's root `app.vue` deliberately renders only `UApp`, `UMain`, `NuxtLayout`, and `NuxtPage`. This makes a newly extended project render safely without requiring project-specific components.

Create a local `app/app.vue` when the project needs a header, footer, search overlay, or Studio login action. Project files override the layer while reusable building blocks remain available:

```vue [app/app.vue]
<template>
  <UApp>
    <AppHeader />
    <UMain>
      <NuxtLayout>
        <NuxtPage />
      </NuxtLayout>
    </UMain>
    <AppFooter />
    <LazyHContentSearch />
    <HStudioLoginButton />
  </UApp>
</template>
```

Keep the required `UApp` wrapper because Nuxt UI uses it for global overlays, tooltips, and toasts. `AppHeader` and `AppFooter` in this example are project-owned components, not implicit layer requirements.
