---
title: "Layer structure"
description: "How @happydesigns/ui provides Nuxt files to projects that extend it."
---
The package is a Nuxt layer exported from its root `nuxt.config.ts`. Projects extend the package and receive the layer files as part of their Nuxt app.

```ts
export default defineNuxtConfig({
  extends: ['@happydesigns/ui'],
})
```

## Source areas

| Source              | Role                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------- |
| `app/components` | Shared `H*` components, including the article and blog layout components. |
| `app/composables` | Shared navigation, SEO, badges, and clipboard behavior. |
| `app/assets` | Shared styles imported by the application. |
| `content/` | Nuxt Content integration, named layouts, components, composables, and server routes. |
| `schemas/` | Reusable Nuxt Content schema profiles, traits, and indexes. |
| `nuxt.config.ts` | Base layer entry, module setup, and component registration. |

Projects can override or add Nuxt files in their own app, but that should be a project decision. If an override becomes a repeated pattern, move the shared part into the layer.
