The layer does not register content sources. Applications own their collection names and filesystem mappings, while `@happydesigns/ui/schemas` provides reusable schema profiles and index recommendations.

## Suggested uses

| Profile or pattern | Typical use |
| --- | --- |
| `content` | General content pages rendered by a project route. |
| `article` | Blog, news, update, or knowledge collections. |
| `event` | Dated entries with location and link support. |
| No shared schema | Simple Markdown fragments such as snippets. |
| `user` | Author or person data referenced by content. |

These are composition profiles, not collection names. One application can call its article collection `article`, another can call it `news`, and both can add project-specific fields with Zod's `extend` API.

Each content file should match exactly one collection source. Keeping source ownership in the application avoids ambiguous Nuxt Studio mappings when a layer and its consumer use different collection names for the same file.

Run Nuxt preparation after changing collection configuration:

```bash
pnpm exec nuxt prepare
```
