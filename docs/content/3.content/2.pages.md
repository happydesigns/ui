---
title: "Pages"
description: "Use the page collection for general route content."
---
Use the shared `content` schema for general Markdown-driven pages, regardless of the collection name. A project decides the route structure, while the layer provides the traits and rendering helpers that keep page behavior consistent.

## Use pages for

- Static content pages.
- Landing sections that still benefit from Nuxt Content.
- Docs-like content inside a project.
- Route content that needs title, description, layout, table-of-contents, or header behavior.

## Table-of-contents behavior

Set `toc: true` when the shared content layout should reserve its right column. Set `toc: false` for listings, galleries, forms, maps, legal notices, or other pages that should use the full container.

## Keep out of page frontmatter

Do not encode product state, permissions, workflow decisions, or deployment settings in page frontmatter. Page frontmatter should describe content and presentation, not own domain behavior.

## Related APIs

`HContentPage` is the default route-level renderer for generic content pages. Pair it with `isContentPageRoute` in catch-all routes. `HArticlePage` remains the renderer for article-like detail pages.

The `@happydesigns/ui/schemas` export also provides `mediaSourceSchema`, `contentImageSchema`, and `createPageSectionSchema()` for consumer-owned collection schemas. These helpers centralize Nuxt Studio and Nuxt UI inheritance without defining collection names or sources in the layer.
