title: "Search"
description: "Configure site navigation search and optional content indexes."
---
`HSiteSearch` provides the shared Nuxt UI search interface in the base layer. Projects keep the search button in their own header and render one search component in their app shell. Nuxt UI owns the shared opening state, keyboard shortcut, filtering, and selection.

## Search navigation links

Applications extending `@happydesigns/ui` can search configured links without activating Nuxt Content or Studio:

```ts [app.config.ts]
export default defineAppConfig({
  app: {
    search: {
      title: 'Search',
      placeholder: 'Find a page…',
      links: [
        { label: 'Contact', to: '/contact' },
        { label: 'Privacy policy', to: '/privacy' },
      ],
    },
  },
})
```

```vue
<template>
  <UContentSearchButton />
  <HSiteSearch />
</template>
```

Mount the search once, including on initial page load, so Cmd/Ctrl+K works before the button is clicked. `HSiteSearch` does not request `/api/navigation.json` or `/api/search.json`. It also accepts Nuxt UI `files`, `navigation`, `loading`, and `groups` props for application-owned data; supplied groups appear before `app.search.groups`.

## Search content

For collection search, extend `@happydesigns/ui/content` and mount `<LazyHContentSearch />` as the app's search component. It loads the optional indexes and owns caching, error, and retry behavior while using the same `HSiteSearch` interface.

## Configure indexed collections

Search is opt-in. The layer generates `/api/navigation.json` and `/api/search.json`, but both return empty arrays until page collections are listed in `app.search.collections`.

```ts [app.config.ts]
export default defineAppConfig({
  app: {
    search: {
      title: 'Search',
      description: 'Search the site content.',
      placeholder: 'Search content…',
      resultLimit: 20,
      collections: [
        { name: 'page' },
        {
          name: 'article',
          where: [{ field: 'published', operator: '=', value: true }],
          order: { field: 'date', direction: 'DESC' },
        },
      ],
    },
  },
})
```

The same filters are applied to navigation and full-text sections. Only Nuxt Content page collections may be configured. Keep publication filters explicit so generated public indexes cannot expose drafts.

## Configure dynamic endpoint caching

Static generation writes both indexes once. On a dynamic deployment, the endpoints default to browser revalidation with a five-minute shared-cache lifetime and one hour of stale-while-revalidate:

```ts [app.config.ts]
export default defineAppConfig({
  app: {
    search: {
      cache: {
        sharedMaxAge: 300,
        staleWhileRevalidate: 3600,
      },
    },
  },
})
```

Set `app.search.cache` to `false` when a deployment must never cache index responses. Development always uses `no-store` so Studio and local content changes remain immediate.

## Add the UI

```vue
<template>
  <UContentSearchButton />
  <LazyHContentSearch />
</template>
```

Use `app.search.links` and `app.search.groups` for project-specific shortcuts. Override `app.search.error` to localize the unavailable, description, and retry labels.
