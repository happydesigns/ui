---
title: Maintenance page
description: A branded holding page without taking ownership of application availability.
---

`HMaintenancePage` renders a full-height notice using Nuxt UI's semantic tokens. It does not replace routes, select HTTP status codes or activate itself globally.

```vue
<HMaintenancePage
  title="We are updating our website"
  description="Please contact us while work is in progress."
  icon="i-lucide-construction"
  :actions="[{ label: 'Contact us', to: 'mailto:hello@example.com' }]"
>
  <template #logo><YourLogo /></template>
  <template #tools><UColorModeButton /></template>
  <template #footer>Your company</template>
</HMaintenancePage>
```

The required `title`, optional `description` and `icon`, and `actions` (`ButtonProps[]`) control the content. Slots: `logo`, `tools`, default content, `actions` and `footer`. The focusable main landmark defaults to `main-content`; set `main-id` to match your application's skip link. Supply one surrounding `UApp` in your application.

## Application responsibilities

Use `icon-color="secondary"` for a brand accent (default: `primary`). The subtle background pattern uses semantic surface and primary tokens; no customer palette is embedded in this component. Keep the logo within a width-constrained wrapper. Content is vertically centered between header and footer, with minimum vertical padding for short screens. The compact header and restrained semibold heading are shared layout decisions, not brand overrides.

- Render either this component or the normal shell, not an overlay over mounted pages. Keep existing routes and source files intact.
- Keep customer copy and the activation flag in the consuming app. Runtime configuration can select a server-rendered mode; static deployments require rebuilding and replacing the output.
- Prevent prerendered HTML, payloads and CDN caches from bypassing the switch. Runtime flags cannot invalidate static files.
- Use HTTP 503 for short maintenance, with `Retry-After` only when a meaningful retry time is known. Use a regular 200 holding page for a longer pre-launch phase. HTTP behavior is host-owned, not a visual component prop.
- Do not treat hidden content as authorization. Protect sensitive data and booking APIs on the server. Specify exceptions such as assets, health checks and payment webhooks deliberately.
- Keep legal links available once supplied by the application. No framework component can invent a customer's legal details.

Test the real consumer in active and inactive modes, including direct links and HTTP responses. Reuse its browser test setup instead of adding another CSS test app.
