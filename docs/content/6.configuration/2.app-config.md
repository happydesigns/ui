title: "app.config.ts"
description: "Configure app-level defaults for projects using @happydesigns/ui."
---
`app.config.ts` is the main project configuration surface. Use it for values that affect rendering across the project but are not part of the reusable package API.

## Common keys

| Key                | Use                                                     |
| ------------------ | ------------------------------------------------------- |
| `app.meta`         | Copyright, social links, and GitHub source metadata.    |
| `app.links.header` | Header navigation links.                                |
| `app.links.footer` | Footer columns and links.                               |
| `app.icons`        | Project icon names used by content or components.       |
| `app.search`       | Shared content-search labels and indexed collections.   |
| `app.toc`          | Table-of-contents labels and behavior.                  |
| `app.date`         | Date and datetime formatting defaults.                  |
| `variants`         | Collection and trait defaults consumed by `useVariant`. |
| `ui`               | Nuxt UI app config defaults.                            |

## Minimal project shape

Start with the project-level values that visible components need: repository metadata, navigation links, date formatting, and collection defaults.

```ts [app.config.ts]
export default defineAppConfig({
  app: {
    meta: {
      copyright: {
        copyrightYear: new Date().getFullYear(),
        copyrightHolder: 'happydesigns',
        copyrightHomepage: 'https://happydesigns.de',
      },
      github: {
        repo: 'happydesigns/example-site',
        branch: 'main',
        dir: 'content',
      },
    },
    links: {
      header: [
        {
          label: 'Articles',
          to: '/articles',
        },
      ],
      footer: [
        {
          label: 'Resources',
          children: [
            { label: 'Articles', to: '/articles' },
          ],
        },
      ],
    },
    date: {
      locale: 'en',
    },
  },
  variants: {
    article: {
      config: {
        list: {
          itemsPerPage: 12,
          labelAll: 'All',
        },
      },
    },
  },
})
```

## Rule of thumb

If a value changes between projects but the component behavior stays the same, it usually belongs in `app.config.ts`. If changing the value changes the meaning of the feature, inspect whether the logic belongs in a product app or in the reusable layer.

## Owner-editable settings

`app.config.ts` remains the typed runtime configuration API, but current Nuxt Studio versions edit Nuxt Content data rather than this source file directly. If site owners should change a small set of values, model those values as an app-owned data collection with an explicit schema and map them into app config.

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@nuxt/content'
import { z } from 'zod'

export default defineContentConfig({
  collections: {
    settings: defineCollection({
      type: 'data',
      source: 'settings/site.yaml',
      schema: z.object({
        copyButton: z.object({
          label: z.string().min(1),
          successLabel: z.string().min(1),
        }),
      }),
    }),
  },
})
```

```yaml [content/settings/site.yaml]
copyButton:
  label: Copy page URL
  successLabel: Link copied to clipboard
```

```ts [app/plugins/content-settings.ts]
export default defineNuxtPlugin(async () => {
  const { data: settings } = await useAsyncData('site-settings', () => queryCollection('settings').first())

  watchEffect(() => {
    if (!settings.value)
      return

    updateAppConfig({
      variants: {
        copyButton: {
          config: { copyButton: settings.value.copyButton },
        },
      },
    })
  })
})
```

Keep the collection intentionally small. Editors should see product language and safe choices, not the complete technical variant tree. Treat every value as public: Content files are committed to the repository and values loaded with `useAsyncData` may be included in the client payload. Never store secrets in this collection. The layer's app config remains the fallback when the collection is missing or cannot be loaded.
