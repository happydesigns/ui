---
title: "Variant defaults"
description: "Configure collection and trait defaults through the variants model."
---
Variant defaults let a project configure repeated behavior for content types without rewriting components. Article and event lists can share pagination, published-only filters, sorting, category badges, breadcrumbs, and trait defaults.

Use `variants.*.config` in `app.config.ts` for defaults consumed by the Nuxt Content layouts and lists. Use [article layout defaults](/components/article/portable-article-layouts#defaults-and-overrides) for `HArticleLayout` and `HBlogArticleLayout`.

The registry defines names and inheritance. The layer and the app supply their defaults through `app.config.ts`. Define an app-owned settings collection for the values editors should change in Studio.

## Example shape

```ts
export default defineAppConfig({
  variants: {
    article: {
      config: {
        query: {
          fields: ['title', 'description', 'published', 'date'],
          order: { field: 'date', direction: 'DESC' },
          where: [{ field: 'published', operator: '=', value: true }],
        },
        categories: {
          release: { label: 'Release', color: 'primary' },
        },
      },
    },
  },
})
```

Use variants for repeatable content presentation and query defaults. Do not use them for authorization or domain rules.
