---
title: Portable article layouts
description: Render article and blog pages without coupling the layout to a content engine.
---

`HArticleLayout` is the shared frame for an article: header, breadcrumbs, body, table of contents, actions, and adjacent links. `HBlogArticleLayout` adds dates, a category badge, and authors to the same frame. Both are available from the base `@happydesigns/ui` layer, including inside an app's own Nuxt layout.

The app loads the document and renders the body. It also owns SEO, editing, and the URLs it passes to the layout. You can use a Vue template, Nuxt Content, Comark, or another renderer. Existing users of `@happydesigns/ui/content` can keep using the named `article` Nuxt layout and `HArticlePage`.

```vue
<script setup lang="ts">
import type { ArticleView, BlogArticleDetails } from '@happydesigns/ui/types'

const article: ArticleView = {
  title: 'A new season',
  contents: [{ id: 'schedule', depth: 2, text: 'Schedule' }],
}
const details: BlogArticleDetails = {
  category: 'Club news',
  authors: [{ name: 'Editorial team' }],
}
</script>

<template>
  <HBlogArticleLayout
    :article="article"
    :details="details"
    :section="{ label: 'Blog', to: '/blog' }"
  >
    <h2 id="schedule">
      Schedule
    </h2>
    <p>Here are the dates for the new season.</p>
  </HBlogArticleLayout>
</template>
```

## Select a layout by name

Use the components directly in a page, or wrap one in a file under the app's `app/layouts/` directory. For example, define `app/layouts/blog-article.vue` around `HBlogArticleLayout` and `app/layouts/tournament-article.vue` around `HArticleLayout`. The tournament layout can add dates and a venue in its own slots. A page that already has article data can pass it to its wrapper with `<NuxtLayout name="tournament-article" :article="article">`.

## Defaults and overrides

Use `app.articleLayout` in `app.config.ts` for shared presentation defaults, such as a TOC title or enabling the Copy URL action. Set `app.blogArticleLayout.categories` to map category names to badges using Nuxt UI's built-in colors and variants. Pass `options` to override the frame defaults for an individual route or profile, or pass a resolved `category` prop for a custom badge. The relevant public types are `ArticleLayoutDefaults`, `ArticleLayoutOptions`, and `BlogArticleLayoutOptions`.

The TOC follows `options.showToc`, then `article.toc`, then the app default. If enabled or unspecified, it appears only with headings or a custom `toc` slot, so articles without a table of contents don't reserve a sidebar. Copy URL is off unless enabled with `copyUrl: {}` or a settings object. Pass `back` and `navigation` when you have those links, and supply edit or issue URLs as resolved `options.footerLinks`. Use the named slots `metadata`, `header`, `toc`, `actions`, and `footer` to compose or replace individual regions.
